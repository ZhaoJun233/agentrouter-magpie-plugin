# 0.1.9 优化与兼容边界

[使用说明](<../README.md>) · [版本记录](<../CHANGELOG.md>) · [MIT 许可](<../LICENSE>)

本文说明 **0.1.9** 的可配置限流等待，以及延续的站点选择、系统访问令牌接入与兼容能力。安装命令固定 0.1.9，先查询 npm 官方 registry 确认可用；源码、npm 包和宿主实际加载版本应分别核对。下文保留既有优化与安全边界，示例不含真实请求、账号或凭据。

## 1. 优化什么，不优化什么

0.1.9 支持在原生插件选项中保存 `retryAfterSeconds`，已识别的 429 缺省等待为 10 秒；账号设置可覆盖插件默认，上游明确等待优先。插件只传达等待提示，不重试请求。原版 magpie 0.1.3906 的 60 秒冷却下限需要单独的宿主修复，npm 插件升级本身不会修改宿主程序。

0.1.8 在 0.1.7 的站点选择与登录能力上增加「系统访问令牌（读取已有 Key）」方式，并移除未通过真实验证的 LinuxDo 手动 OAuth：API Key 保留原生单输入；GitHub 保留管理令牌 + 浏览器授权 + 完整手动回调；新方式只用站点、系统访问令牌、用户 ID 与可选 Key ID 只读读取账号已有 key。新国内站账号显式保存模型 API 地址，旧配置不迁移；同时包含 assistant 历史类型与 Windows 权限识别修复。下列有界响应处理与独立正文过滤能力继续保留。

这里的“优化”是减少错误归类和兼容处理中的误判、无界等待与信息丢失，不是增加上游额度或提高模型能力：

- **HTTP 200 不一定是成功回答。** 上游可能在 JSON 错误封套或 SSE 前导事件中报告失败。只识别明确、有限的错误依据，不从正常正文中搜索错误词。
- **诊断不能吃掉原始正文。** 请求改写与 JSON 诊断检查副本，设置字节和时间预算；不确定就放弃改写，让调用方继续读取原文。
- **历史 ID 不能任意删除。** 只有内容完整、形状已知的条目才能内联；服务端引用、推理和加密状态不能靠删字段恢复。
- **文本替换与历史内联相互独立。** 本地词表只修改获准的普通正文；内联开关不应改变文字过滤器识别空 `logprobs: []` 的能力。

本插件仍运行在既有宿主中，不新增独立服务、仪表盘、遥测、自动重试、账号切换或有损历史降级。

完整 assistant 消息去掉顶层查找 ID 后，正文仍使用 `output_text` 并保留空注释/概率字段；不得误转为仅适用于其他角色的 `input_text`。此修复不改变 reasoning、引用和未知字段的保留规则，也不承诺不透明状态跨资源可用。

## 3. 模块职责与处理顺序

请求侧顺序为：检查适用端点与正文 → 有界读取 → 本地普通正文过滤 → 可选完整历史内联 → 仅在实际修改时重新序列化。响应侧独立执行有界诊断。

| 模块 | 职责 |
| --- | --- |
| [body-inspection.mjs](<../body-inspection.mjs>) | 内部共享读取器 `readCloneText`；返回完整有效的 UTF-8 文本或无法检查的结果，不消费调用方原始正文 |
| [request.mjs](<../request.mjs>) | 判断请求范围、执行过滤及内联、维护改写后的请求头 |
| [content-filter.mjs](<../content-filter.mjs>) | 加载私有字面量词表，保护代码、工具数据和不透明内容 |
| [response.mjs](<../response.mjs>) | JSON 错误分类、SSE 前导观察、失败说明与原始流转交 |
| [index.mjs](<../index.mjs>) | 对接宿主选项及 fetch；一次宿主 fetch 调用至多发起一次上游 fetch；缺失 key 时本地拒绝 |

共享读取器是内部模块，不新增根入口公开 API。0.1.5 没有新增依赖、环境变量、提供商选项或登录配置迁移。

## 3A. 0.1.8 登录与凭据边界

### API Key：先列出，原生单输入，只保存

方法顺序为 API Key、GitHub、系统访问令牌，三种方式均可选择 org / air 站点。API Key 仅增加站点选择，密钥仍只在宿主原生输入框输入一次。当前宿主的 API `authorize` 不接收原生 key，无法在保存前验证；不添加第二个 key 字段、verified 标记或“已验证”徽章。**凭据已保存 / 宿主已登录 ≠ 模型已验证**，保存后须独立测试模型。

### GitHub：站点 → 管理令牌 → 用户浏览器 → 完整手动回调 → 已有 key

插件预置问题为站点选择和系统访问令牌（password 遮蔽输入）。令牌是 AgentRouter 管理凭据，**不是模型 API Key，也不是 GitHub PAT**。随后用户须打开授权链接，在浏览器完成授权，将包含 code/state 等全部参数的完整回调 URL 粘回宿主；不能承诺免令牌、自动收回调或全自动 OAuth。回调 URL 是敏感临时凭据，不应公开。

配置读取只要求站点提供 GitHub client ID；不读取也不要求任何其他提供商的 OAuth 配置。兑换请求携带本次 state 接口签发的站点 session Cookie，仍限制在所选站点且不自动跟随兑换重定向。授权结果保存 `metadata.site`，新国内站账号额外保存 `apiBase`。

GitHub 使用 `/oauth/github/magpie`，以避开原 SPA 回调的自动兑换；这依赖 GitHub 文档记载的“回调可按已注册 URL 的子目录匹配”规则，站点自身的兑换请求不发送 `redirect_uri`，因此该 URL 只需通过 authorize 一步。该规则没有在其他提供商上复现过，不据此外推。

查找已有 key 支持已知的 `data.items` / `data` 数组形状。候选须满足 `status=1`、非空、未掩码、未过期，并按实际 key 去重；只有唯一可用候选才能保存。只读取一页（`page_size=10`）：总数大于返回条数，或未提供总数且已返回 10 条时，按列表不完整处理。多个候选、无候选、未知形状或分页截断导致结果不确定时，改用原生 API Key 输入手动指定。不自动创建、轮换、补页重试或以空 key 成功。管理 API 调用成功也不证明模型调用成功。

loader 对缺失 key 或保留占位 key 在网络前返回本地 `400 agentrouter_missing_api_key`；应手动保存真实模型 key 后再测，不把它误判为上游错误。

### 系统访问令牌：用户 ID + 可选 Key ID，只读取已有 key

模型 Key ID 只接受留空或以非零数字开头的正整数字符串；表单、授权入口与请求函数共用校验规则。即使宿主直接提交登录参数，非法 ID 也会在创建登录流程或发出请求前被拒绝。

新增的第三种方式不使用任何 OAuth 授权码。预置问题为站点、系统访问令牌（password 遮蔽输入）、用户 ID 与可选的模型 Key ID。该站点的用户接口必须同时带系统访问令牌和用户 ID：真实验证中只带令牌的同接口返回 401，因此用户 ID 不能省略。多把 Key 时必须填写 Key ID——该 ID 是站点「令牌」页 ID 列对用户可见的数字列，不是从响应反推的字段。

Key 选择规则：只有一把启用且完整的 Key 时直接使用；填写了 Key ID 时按 `GET /api/token/{id}` 只读读取该把，同一请求用于确认启用、非掩码与未过期；两者都没有唯一答案时失败并提示填写 Key ID，不代选、不补页、不重试。列表读取 `page_size=50`，总数大于返回条数或已达分页上限时按不完整处理。该方式不请求 `/api/oauth/*`，不创建、轮换或修改任何 Key；metadata 只写 `site`、`apiBase`（国内站）、`accessToken`、`userId`。

### 已移除：LinuxDo OAuth 登录

0.1.7 曾按 GitHub 的子路径思路新增 LinuxDo 入口，真实验证否定了它，故在 0.1.8 整体移除，而不是放宽路径校验。真实验证记录（单次人工批准的调试连接、真实账号）：授权最终回落到站点注册路由 `https://agentrouter.org/oauth/linuxdo`，并非请求里的 `/oauth/linuxdo/magpie`；站点前端在该路由挂载时立即请求 `/api/oauth/linuxdo`（记录到 1 次、HTTP 403）并跳转控制台，地址栏不再保留 code/state；把该真实回调 URL 交给插件校验，在任何兑换请求之前即被拒绝。官方文档与站点前端构建产物确认该路由为精确匹配、没有任何可抑制自动兑换的标志位；公开资料对 LinuxDo redirect_uri 匹配语义没有任何说明。绕过站点页面的自动兑换意味着创建或复用登录态，不在本插件范围内。

### 旧配置与签到：保留账号设置

新账号默认 `agentrouter.org`；选择国内站的新账号显式保存 `apiBase: https://ps.air-outer.com/v1`。模型地址仍依次采用显式 endpoint、已存 apiBase、默认国际站；旧账号只有 `site: air` 时不会自动切换模型端点。升级不改写旧账号 key、site、headers 或其他设置。GitHub 与系统访问令牌方式会询问站点和凭据，其余问题（端点、请求头、用户名密码、Cookie）不再作为登录问卷出现。当前插件选项只有布尔开关，**没有新增 Cookie 设置页**。需要高级配置时先备份，再使用 [README 的既有手动配置格式](<../README.md#手动配置文件格式plugin-authjson>)；不要把凭据写进布尔选项。

GitHub Cookie 是可选签到续期的高权限会话，不随升级自动采集或启用。本次未新增任何自动登录或签到续期机制。远程网关会将凭据保存在远程服务器；格式正确不代表会话有效、账号匹配或可通过 WAF。不得公开 Cookie、令牌或回调，也不能绕过授权确认、2FA 或验证码。

模型测试、余额读取与签到到账应分别确认；余额可能是历史缓存，宿主登录不保证签到成功。独立 [本地签到工具](<../LOCAL-CHECKIN.md>) 保持不变，不自动启用。

## 4. 选项组合：关闭内联不等于关闭过滤

提供商编辑器保留原有选项和默认值：

- `portable-responses`：**Replay complete Responses items inline**，默认开启。
- `text-filter`：**Filter configured prose before sending**，默认开启，但没有本地词表或 `terms` 为空时不替换正文。
- `send-codex-headers`：**Send the Codex client headers**，默认开启，与上述两个正文选项独立。

429 的缺省等待时间通过原生插件 JSON 选项 `retryAfterSeconds` 配置，默认 10 秒。`package.json` 的 `magpie.options` 提供示例，宿主通过插件入口第二个参数传入已保存选项。账号 `metadata.retryAfterSeconds` 可覆盖它，同名顶层账号字段继续沿用既有优先级。原生页面保存后宿主重载插件；手工修改账号配置后须重新加载插件或重启宿主。数值不放入仅支持布尔值的 `auth.options`。

| `portable-responses` | `text-filter` | 请求正文行为 |
| --- | --- | --- |
| 开 | 开 | 先过滤获准正文，再按条件内联完整历史 |
| 开 | 关 | 不过滤正文，只做符合条件的历史内联 |
| 关 | 开 | 只过滤获准正文；不删除消息 ID，不转换条目类型 |
| 关 | 关 | 不做这两项正文变换，原始正文透传 |

“两项都关”仅指请求正文变换：认证/客户端请求头处理与响应诊断仍存在，不是整个插件的旁路开关。没有实际替换或内联变化时，保留原始请求正文，不为了格式化 JSON 而重写。只有真正执行了历史内联，才设置 `store:false`；仅过滤正文不会附带修改该值。

本地规则从插件安装目录的 `content-filter.local.json` 加载，格式见 [示例配置](<../content-filter.example.json>)。以下仅是虚构字面量，不代表厂商拦截词：

```json
{ "terms": ["示例占位短语"], "caseSensitive": true }
```

规则按最长字面量优先、非重叠替换为 `[FILTERED]`，不是正则，也不自动添加单词边界。缺少文件或空词表表示不启用替换；已经配置但无法读取、格式无效或超限时会报告配置错误，**不会静默忽略坏配置后发送请求**。加载中的规则是快照，修改后须重新加载插件。私有词表不要提交到 Git、示例文件、日志或命令行。

## 5. 三个读取预算不能混为一谈

| 检查对象 | 字节上限 | 等待上限 | 范围与退出方式 |
| --- | --- | --- | --- |
| 请求正文改写 | **4 MiB** | **2 秒**，用于 Request 副本读取 | `POST .../responses` 的 JSON 请求；超限或无法可靠读取就不改写 |
| JSON 响应诊断 | **64 KiB** | **2 秒** | 仅 HTTP **200 / 400 / 429**；200 还须声明 JSON 内容类型；解析不成立则保留原响应 |
| SSE 前导诊断 | **64 KiB** | **15 秒** | 仅 HTTP 200 的 `text/event-stream`，并且尚未放行有效内容或未知事件 |

1 MiB = 1,048,576 字节，1 KiB = 1,024 字节。预算依据实际读取的 UTF-8 字节，不依赖 `Content-Length` 是否存在或准确；已提供的字符串请求体也要通过字节上限检查。

请求中的压缩正文、非 JSON、其他端点（包括 `/responses/compact`）和不支持的正文形态不改写。Request/JSON Response 副本遇到超限、超时、取消、解码或读取失败时放弃检查；定时器和监听器会清理，不等待可能受原始消费者阻塞的 tee 分支取消。

这些是**诊断预算，不是整段响应大小、总请求时长或进程内存上限**。正常长回复仍可继续流动；上游一次交付的数据块可能已大于预算，插件不能阻止运行时分配该块。底层网络/流读取错误也不会被伪造成成功数据。

## 6. 显式错误、叶子验证与业务否决

### 6.1 先确定是错误，再确定能否分类

检查入口包括明确的 `error` / `response.error`、`response.failed`、SSE `event:error`，以及已处于 HTTP 400/429 错误响应中的错误详情。支持 `message` / `msg` 和其中 JSON 编码的错误，不扫描成功回答、工具结果或普通说明文字。

嵌套展开使用四层递归预算。每一步都先确认子层存在有效错误详情；空对象、空白消息、数组或未知且无有效详情的结构，不能借包装层的“繁忙”文字变成已知故障。祖先只能补充白名单内的合法数值状态，不能借用祖先正文。深度预算耗尽且仍有未检查嵌套时，**整条诊断 fail-open：保留原始响应，不依据部分祖先字段猜测**。

### 6.2 新增白名单

下表只适用于通过上述验证的错误详情，且没有命中业务否决：

| 依据 | 输出 HTTP 状态 | 错误类型 |
| --- | --- | --- |
| `status` / `status_code` / `code` 的数值或严格三位数字字符串 `429`；或 `rate_limit_exceeded` | 429 | `agent_router_upstream_rate_limit` |
| `overloaded_error` / `high_demand`，或错误消息中的完整短语 `currently experiencing high demand` | 503 | `agent_router_upstream_busy` |
| `server_error` | **500** | `agent_router_upstream_error` |
| 数值或严格三位数字字符串 `500` / `502` / `503` / `504` | 对应状态 | `agent_router_upstream_error` |

错误码白名单从详情的 `code` 读取；该字段缺失或为 `null` 时才取 `type`。`"503"` 是合法数值字符串，`" 503 "`、`"503 busy"` 等不是。若合法数值状态与已知代码同时存在，**HTTP 状态优先采用数值状态**；错误类型仍按限流、繁忙、服务故障特征区分，不能用类型倒推另一个 HTTP 状态。

### 6.3 业务原因优先，不把拒绝包装成“稍后会好”

明确的认证、权限、余额、计费、配额和内容策略错误优先于新增暂时性分类。即使同一封套带有 503 或“繁忙”文字，也不会因此包装为暂时性服务故障；无法分类时保留原响应。

既有专用错误行为保持：

| 原有依据 | 状态 / 类型 |
| --- | --- |
| 明确的 token 速率上限消息 | 429 / `agent_router_token_rate_limit` |
| `content-blocked` | 400 / `agent_router_content_blocked` |
| 精确的“条目创建于另一 OpenAI 资源”消息 | 400 / `agent_router_resource_mismatch` |
| SSE 明确完成、空 `output`、输入和输出用量均为零，且此前未出现有效输出 | 502 / `agent_router_empty_response` |

内容拒绝和跨资源错误仍走自己的专用说明，不会因为业务否决变成通用繁忙错误。零用量本身、一次空片段或截断流，都不足以证明 token 限流或空完成。

虚构反例，用于理解分类边界：

```json
{"error":{"status":"503","message":"Fictional upstream is temporarily unavailable."}}
```

这是可识别的明确服务错误。以下两条则不应用新增暂时性分类：第一条有配额业务原因；第二条只有包装层有状态和文字，错误叶子为空。

```json
{"error":{"status":503,"code":"insufficient_quota","message":"Fictional quota exhausted."}}
```

```json
{"status":503,"message":"currently experiencing high demand","error":{}}
```

## 7. SSE：诊断截止线就是数据保留线

前导解析按增量方式分行，支持 LF、CRLF、CR 及混合换行、跨块 UTF-8、注释和多行 `data:`；重复 `event:` 使用最后一个值，字段冒号后只移除一个可选空格。

一旦看到有效正文、推理或工具内容，或未知事件/未知数据形状，就结束观察。之后的字节和错误不重新包装，避免抹掉部分答案或诱发工具重复执行。未知形状即使出现在已知事件中，也不是继续等待后续“更像错误”的事件的理由。

- 已读正常前缀、未知数据、未完成帧、超限或超时路径，均转交原始字节，而不是重新编码解析后的文本。
- 超时时保留已发起但尚未完成的读取；不能通过另起一次读取跳过该数据块。
- 保留消费者取消和背压；不发送心跳，不全量缓存回答，不添加放行后的空闲超时。
- 明确的早期错误可以替换为 JSON 错误响应；已放行内容后的错误不做这种替换。

“逐字节保留”适用于未命中明确早期改写的路径，不等于每种响应都保持同一对象，也不表示底层 I/O 永不失败。

## 8. 历史、工具与不透明状态

`portable-responses` 只处理含完整内联内容的已知普通消息、`function_call` 和 `function_call_output`，删除用于上游条目查找的顶层 `id`。普通输出消息转换为可接受的内联输入形式，保留角色、正文和 `phase`；工具的 `call_id`、名称、参数、结果和嵌套业务 `id` 不动。

保留规则优先：

- 不删除 `previous_response_id`、`conversation` 或 `item_reference`；存在这些服务端历史引用时不执行 ID 内联改写。
- 不删改 reasoning、`encrypted_content`、compaction、摘要或未知条目；`store:false` 不会让加密状态跨资源可移植。
- 非空引用注释、未知消息字段、文件/图像/容器等资源引用不做递归“清理”。
- 不内置“失败后删历史再发一次”路径，不默认硬拒绝不透明历史，也不会从其他资源偷偷获取缺失上下文。

如果旧会话只有服务端引用，仍需要客户端重发完整历史，或让上游固定到创建这些条目的原资源。仅升级插件、换 key 或设置 `store:false` 都不构成无损恢复保证。

## 9. 空 logprobs、Markdown 与幂等性

0.1.4 已让符合条件的普通 `output_text` 的空 `logprobs: []` 参与历史内联。0.1.5 补齐的是**独立文字过滤路径**：过滤先于内联执行，因此两种内联开关状态都能处理这种普通文本。

当关闭内联时，仅替换文本，保留原消息 ID、`output_text` 类型、空概率数组及其他获准元数据。非空、`null` 或未知形状的概率数据、真实引用注释、签名和未知字段不会被这项例外放行；`input_text` 中的未知概率字段也不会因此变成可过滤内容。

文字过滤范围是 `instructions`、字符串 `input` 和普通 user/assistant/system/developer 消息中的获准文本片段；工具参数/结果/schema、模型名、metadata、媒体和不透明历史不在范围内。

Markdown 采取保守策略，而不是试图实现完整语法解析器：

- 保护行内代码、根级反引号/波浪线围栏和未闭合代码段。
- 含缩进代码的段落不改，其前后独立正文段落仍可过滤；引用或列表容器中的围栏会使整个文本字段保持原样。
- 保护已有 `[FILTERED]`、代码结构分隔符及下一非空行缩进，跨越这些边界的字面量匹配保守跳过。
- 普通正文跨段落的字面量仍可替换；同一规则重复应用应保持稳定，不因第一次替换吞掉换行而在第二次暴露代码。

这种幂等性和保留性有回归覆盖，但它**不是通用脱敏或数据防泄漏系统**：被刻意保留的代码、工具、附件或引用背后仍可能含有词表内容。

## 10. 请求头、等待提示与重试所有权

响应改写会保留上游等待提示与请求标识，包括 `Retry-After` 的秒数或 HTTP 日期形式，以及上游提供的毫秒等待头。上游错误代码和消息分别保留在 `error.code` 与 `error.upstream`；没有代码时使用相应的回退代码。诊断内容可能仍含上游提供的信息，公开报障前应自行脱敏。

已识别的 **token 速率专用错误及通用 429 限流** 在没有 `Retry-After`、`retry-after-ms` 或 `x-ms-retry-after-ms` 时补 `Retry-After`，值依次采用账号配置、插件选项，默认 **10 秒**。接受正整数或纯数字字符串；缺失、非正整数、非法类型或超出安全整数范围时回退为 10 秒。配置由各插件实例和账号 loader 传入响应诊断，不使用全局可变等待值。这是等待建议，不保证届时恢复；其他错误分类不补等待时间，业务错误与未知错误仍按原有规则保留。

原版 magpie 0.1.3906 的 `rateRest` 仍取 60 秒起步的退避值和等待提示中的较大值。小于一分钟的倒计时需要宿主同步修复：仅对 `PluginProvider() == "agentrouter"` 接受正的等待提示覆盖缺省退避，仍保留更晚的上游重置时间；其他提供商的策略不变。插件测试只能证明输出头，宿主冷却另行验证。

实体头只在正文确实重建时调整：

- 请求改写移除 `content-length`、`content-md5`、`digest`、`content-digest`。
- 响应改写设为 JSON，并移除 `content-length`、`content-encoding`、`transfer-encoding`、`etag`、`content-md5`、`digest`。
- 不改写的路径保留原始正文和对应响应头；默认客户端标识开关与用户配置头仍遵循插件既有规则。不要把 Cookie 或 Authorization 当作普通客户端标识示例传播。

**一次宿主 fetch 至多一次上游 fetch；缺失 key 时为零。** 插件不追加 POST，不切账号、不重放工具、不降级历史；宿主自身的重试、路由和故障转移是另一层策略，必须分别配置和核查。返回 429/503 或等待头不等于插件执行了重试，也不能保证宿主一定按同样策略等待。

## 11. 升级与回退

1. 阅读 [使用说明](<../README.md>) 和 [版本记录](<../CHANGELOG.md>)，核对来源：npm 安装固定 0.1.9 并先查询官方 registry；本地包/目录安装应核对提交、包版本和宿主实际运行版本。不能把源码版本号当成 npm 发布或远程网关升级证明。
2. 在受保护的位置备份当前插件版本、私有词表及宿主管理的配置；不要将凭据备份加入公开仓库。
3. 使用已核验的完整本地包或完整插件目录升级，不能只覆盖入口文件。新增 [body-inspection.mjs](<../body-inspection.mjs>) 是运行时必需模块，漏带会导致模块加载失败。
4. 无需迁移认证字段、选项或环境变量；升级前后核对旧 key、site 和其他设置不变，不必重新登录。重新加载插件，让运行中的 loader 使用新源码与规则快照。先确认四种开关组合符合自己的使用意图。
5. 如只需停用正文变换，可关闭两个正文选项；这不会停用响应诊断。需要完整回退时，恢复此前验证过的完整版本并重新加载，不混用新旧模块。
6. 回退至 npm 0.1.7 会得到 0.1.7 的 LinuxDo 登录入口（该入口已通过真实验证判定不可用），并失去系统访问令牌方式；回退至 0.1.6 会再失去站点选择、OAuth session 透传及本次 assistant 历史与 Windows 权限修复。已存的显式 apiBase 仍是旧版本识别的字段，回退不会自动撤销新账号的站点选择；应保留并核对原有配置备份。更早版本还会失去各自后续引入的密钥保护、诊断、SSE 或过滤修复；回退不能恢复已缺失的上游历史。

本节不要求重新登录、提交真实 Cookie、执行自动签到或回放私有会话。涉及真实流量的验收应单独评估并由部署者授权。
